# Media QC Inspector
## Technical Validation Report Specification
### Version 1.0 Draft

## Purpose

The Technical Validation Report is the primary deliverable produced by Media QC Inspector.

Its purpose is to provide editors, production staff, mastering operators, localization vendors, and quality control personnel with a concise, professional summary of the technical condition of a media asset.

The report should:

- Identify the analyzed asset.
- Document the media structure.
- Summarize the validation outcome.
- Clearly identify any QC findings.
- Provide actionable recommendations.
- Present information in a consistent, easy-to-read format suitable for production workflows.

The report should remain objective and application-generated. It should never read like a developer log.

## Report Philosophy

The report should answer three questions, in order:

1. What file is this?
2. Did it pass validation?
3. If not, what needs attention?

Everything else supports those three goals.

WARNING: Technical validation completed with one or more advisory findings.

FAIL: Technical validation completed with one or more QC findings requiring review.

## Formatting Standards

Use tables for:

- Media Information
- Validation Results

Use paragraphs for:

- Summary
- Details
- Recommendations

Do not force long narrative text into tables.

## Typography

- Document title: largest font
- Section headers: bold
- Tables: consistent spacing
- Body text: readable paragraph spacing
- No developer-oriented formatting

## Colors

Result labels may use subtle color cues in the PDF:

- PASS: green
- WARNING: amber
- FAIL: red

Tables should remain mostly monochrome except for result indicators.

## PDF Export

- Page size: US Letter
- Orientation: Portrait
- Margins: 0.5 in
- Tables should span pages naturally when necessary.
- Long recommendations should wrap naturally.

## Future Enhancements

### Visual QC Evidence

Optional embedded frame captures for:

- Freeze Frames
- Black Frames
- Decoder corruption

The report must remain fully functional without images.

### Delivery Profile Comparison

| Codec | ProRes 422 HQ | ProRes 422 HQ | PASS |

### Future modules

- Audio Validation
- Caption Validation
- Loudness Validation
- HDR Validation

## Design Principles

The report should:

- Be readable in under one minute.
- Be suitable for production, editorial, localization, and mastering teams.
- Separate factual information from validation results.
- Separate validation results from detailed findings.
- Scale naturally as new QC modules are added.
- Avoid developer terminology.
- Remain consistent regardless of how many modules are present.
